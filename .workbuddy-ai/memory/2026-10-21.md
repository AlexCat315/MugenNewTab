## 关于 Chrome 新标签页底部「自定义 Chrome」条

- 结论（待用户用下面方法验证）：扩展**大概率无法**通过 DOM 或 API 隐藏它。Chrome 会把第三方 NTP 页面放进 `chrome://new-tab-page` WebUI 的 iframe 里，那条底栏由宿主页面渲染，扩展页面跨域拿不到 `parent.document`，也没有对应的 extension API。
- 用户侧的关闭方式：NTP 右下角「自定义 Chrome」→ 关闭相关开关；或 `chrome://settings` 外观设置里关掉自定义 Chrome 入口。
- **用户提出反例**：DuckDuckGo 的新标签页扩展没有这条底栏。→ **已查证：反例不成立。**
  - 拉取 `github.com/duckduckgo/duckduckgo-privacy-extension`（默认分支 main）的 `browsers/chrome/manifest.json`（MV3，min_chrome 128）。
  - 该 manifest **没有 `chrome_url_overrides`**，全仓库 `git ls-tree` 也搜不到任何 ntp 相关文件；它只有 `chrome_settings_overrides.search_provider`（把默认搜索引擎改成 DDG）+ `omnibox.keyword: ddg`。
  - 结论：DuckDuckGo 的扩展**根本不接管新标签页**，所以它不是「第三方 NTP 却没有底栏」的先例。原来的判断（扩展无法移除该底栏）维持。
  - 备注：GitHub raw/API 直连会被 404/403，改用 `git clone --depth 1 --filter=blob:none --no-checkout` + `git show HEAD:<path>` 可以稳定取文件。
- 备选绕过思路（未实施、有风险）：去掉 `chrome_url_overrides.newtab`，改用 background 里 `chrome.tabs.onCreated` + `chrome.tabs.update` 把新标签重定向到 `chrome-extension://...`。但 Chrome 通常禁止扩展脚本导航 `chrome://` 页面，可行性存疑，且会有默认 NTP 闪一下的问题。

## 底部页脚「能不能不手动关」

- 用户核心诉求：不想每次手动去 Chrome 设置里关底栏。
- 结论：扩展侧没有任何 API 能去掉它（它在 `chrome://new-tab-page` 外壳层，不在扩展 DOM 内）。
- **唯一不依赖手动设置的路**：放弃 `chrome_url_overrides.newtab`，改在 `src/background.ts` 里用 `chrome.tabs.onCreated`/`onUpdated` 把 `chrome://new-tab-page` 重定向到扩展页面。Chrome 原生 NTP 不渲染 → 没有页脚。代价：可能先闪一下默认页、MV3 service worker 唤醒时序、Chrome 可能拦截 chrome:// 页面的脚本导航。已向用户提出可做实验版，等其确认。
- 参考：`manifest.json` 已含 `tabs` 权限；`src/background.ts` 目前只有 Firefox 的启动页重定向逻辑，可复用同样模式。

### 3. 重定向版实测结果：底栏没了，但地址栏露出扩展 URL
- 用户实测 `dist-redirect/` 有效：底部「自定义 Chrome」页脚消失。
- 新问题：地址栏显示 `chrome-extension://<id>/index.html`（外加扩展全名）。
- **这是不可兼得的取舍**，无法修复：
  - `chrome_url_overrides` 时标签页 URL 是 `chrome://new-tab-page`，Chrome 对内部页不显示地址 → 地址栏干净，但外壳画页脚；
  - 重定向后标签页真的是扩展页面，Chrome 必须如实显示真实 URL → 无页脚，但地址栏露 URL；
  - 扩展没有任何 API 能控制地址栏显示内容。
- 已做的唯一缓解：`manifest.redirect.json` 的 `name` 从「MugenNewTab - 新标签页导航（重定向实验版）」改成 `MugenNewTab`，地址栏前面那截扩展名变短。
- 两套产物对应关系：`dist/` = 地址栏干净+有页脚；`dist-redirect/` = 无页脚+地址栏露 URL。切换命令：`npm run build` / `npm run build:redirect`。
